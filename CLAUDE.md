# DropBeat developer notes

Things learned while building DropBeat that aren't obvious from the code. The player-facing overview is in [README.md](README.md). The look and the game-feel recipe (what makes hits satisfying) are in [STYLE_AND_FEEL.md](STYLE_AND_FEEL.md); follow it for any new song, twist, effect, sound or UI.

- Unity `6000.5.4f1`, URP, Input System, IL2CPP, portrait iPhone first (1080-wide UI reference).
- Work happens on the `redesign` branch. `main` is the old prototype.
- Everything lives in `Assets/DropBeat`. The scene is generated by **DropBeat > Build Game Scene**; never hand-edit `Game.unity`.

## Rules the game is built on

- **Hits land exactly on the beat.** This is the top priority.
  - Every note sits on the beat grid (a beat, or an exact half-beat on Hard).
  - The ball's position is a pure function of song time (`LevelLayout.BallAt`).
  - Never move the ball with physics or frame time.
- **Analyse the samples Unity decodes.** Unity's MP3 decoder starts these files about 49 ms later than ffmpeg does, so beat analysis must run on Unity-decoded samples, never on ffmpeg output.
- **Notes only on beats you can feel** (kick or snare hits that stand out), not on every beat.
- **No hold notes.** They were removed at the user's request because the slow rail grind broke the rhythm. Charts are tap, swipe and dual only.
- **Charts are designed, not random.** `MapDesigner` and `ChartDesigner` give the same map on every play. Check determinism after any chart change.
- **Keep several balls readable.** Companion phrases use the side view and separate lanes. Ball 3, which only appears in Jade Temple on Hard, uses lane `-(W+1.8)`. No companions while the camera is in the tunnel.
- **Rings must stay on screen.** On a tall phone screen, any camera roll swings the ring chain sideways (see the warp fix below).

## Song twists

Each song's twist is defined in `Data/SongTwists.cs`:
- `SongTwists.For` gives the song's twist. Title, blurb and tint come from the same class.
- `TwistDesigner` changes the chart:
  - `ShapePhrases` runs before notes are placed.
  - `Finish` runs after. It builds `twistSpans`, golden rings, heavy impacts, ice moving rings and dance cuts.
  - `Decorate` runs at layout time and sets the per-ring effects.

At runtime, `Gameplay/TwistDirector.cs` handles banners, camera roll, beat effects, the sonar ping, the boss (HP, its `BossView`, the camera framing its arena), the gold-ring score and the overdrive floor.

**Boss fight (8-Bit Hero):**
- `TwistDesigner.Finish` makes the finale the arena:
  - It removes companion notes and turns duals and swipes into taps.
  - It clears moving rings.
  - It forces the side camera 4 beats before the arena.
- `LevelLayout.PlaceBossRing` places the arena's rings round `BossCenter`:
  - Each 4-bar block of the arena is one attack, cycling `BossMove.Orbit`, `Barrage`, `Sweep`, `Spiral` (`BossPhases` lists when each starts).
  - Orbit: anticlockwise on `BossRadius` 3.2, 40° to 70° per ring depending on the gap. Spiral: clockwise on a radius of 2.45 to 3.25. Barrage: x = ±2.6, alternating sides (quick doubles stay on their side). Sweep: rows at ±3.1 from the centre, four spots each.
  - Every spot keeps at least `MinRingGap` from the previous ring; if not, it steps on (more angle, the next spot in the row).
  - Each ring gets `NoteFx.Boss` and its `bossMove`. `PositionAt`, `FacingAt` and `BossVisibility` play the attack so it ends on the spot exactly on the beat.
- `LevelLayout.TimeBossRings` sets `fxLead` (when each ring shows): the earliest candidate where it never comes within 1.75 units of an earlier ring on screen (`ClosestApproach`); if none is clear, the one that keeps them furthest apart. Barrage and Sweep leads sit on the half-beat grid. It takes under 20 ms per chart.
- `TwistDirector` shows a banner and `BossView.Roar` for each new attack, and `BossView.Fire` when a barrage ring launches.
- `Visual/BossView.cs` draws the boss (merged voxel meshes, one per colour), the pixel-dot halos, the lasers and the explosion.
- `GameController` blends the camera focus to `TwistDirector.CameraFocus` (the arena) over the 4 beats before the fight.

**Clear rewards and the profile:**
- `BallSkin.Champion` (Chrome shader skin 10) and `TrailEffect.Aurora` are clear rewards (`GameSettings.IsClearReward`). They unlock through `HardClearReward` and `NormalClearReward` (saved as `db.reward.*`), never with ads.
- `SubmitRun` sets those rewards and reports them in `RunRecord.unlockedSkin` and `unlockedTrail`.
- `SyncClearRewards` grants them at start-up to players with older clears.
- The skin preview texture is now 5 × 3 cells.
- `GameSettings.RecordRun` keeps the lifetime stats (`db.stat.*`; the total score is a string, since PlayerPrefs has no long). `GameController.FinishSong` calls it for every non-autoplay run.
- `UI/GameUI.Profile.cs` has the profile sheet and the results reward card. The card sits inside the results card between the next-goal line and the buttons.

**Slide Rush (Overtime):**
- `NoteFx.Slide` with `fxFrom` (where the ring waits), `fxSettle` (when it has landed, before its beat) and `fxLead` (when the slide starts, one beat earlier).
- Rings land as their approach circle starts (`LevelLayout.ApproachTime`). After `OvertimeRushStart` they land halfway through it.
- `SlideVisibility` keeps waiting rings dark, because in the angled and tunnel views an off-screen offset can still be on screen.

- **Spans:** a twist is only active inside its spans. Songs are only about 5 phrases (8 bars = 32 beats each), so rules that need high phrase energy can leave a twist almost unseen. Flip, Warp and Stampede were loosened for that reason.
- **Turning screen:** inside Flip and Warp spans, `TapsOnly` turns duals and swipes into taps, because left, right and up stop making sense while the screen turns.
- **Warp camera:** the warp roll makes whole turns over the span, eased so it ends upright.
- **Roll compensation:** `CameraRig.Apply` spins around a point 2 units lower and pulls back by up to 30% (both scaled by `|sin(roll)|`). Without it, the nearest rings went up to half a screen off the edge at a 90° roll on a portrait screen.
- **Changing roll or camera poses:** re-measure with the recipe under "Measuring what's on screen".

## Game feel

The feel code is split into partial-class files:
- `GameController.Feel.cs`
- `GameUI.Feel.cs`
- `SfxPlayer.Stingers.cs`
- `SfxPlayer.Voices.cs`

**Streak tiers** are set per difficulty by `TierAt`: Easy 6/12/24/48, Normal 10/20/40/80, Hard 15/30/60/120.

**Sounds:**
- Hit sounds are synthesized in the song's key, loudness-matched across the 13 instruments (within about 2 dB), with grades about 2.5 dB apart.
- Stingers are built off the main thread (`Task.Run`) and fall back to the fanfare until they are ready.
- Each voice fades over 12 ms at its end to avoid clicks.
- Built hit sounds are cached for at most 3 songs (least recently used). Evicted clips are destroyed.

**Mixing:** `MixBus` ducks the music on hits and soft-clips above 0.84 in `OnAudioFilterRead`. The music volume is multiplied by `SongData.MusicGain` (from `gainDb` in `themes.json`).

**Hit flash:** keep it moderate. A white-hot flash, glint and ball glow together bloomed into a screen-filling white blob with square artifacts. The current values are the toned-down ones:
- `ImpactFX` colour: `Lerp(white*2.2, (1.6,1.25,0.5))`
- Ball glow tint: ×0.5
- Approach circle: starts at white ×1.8

## Timing details

`SongClock` locks to the DSP clock:
- Music starts with `PlayScheduled` on the beat grid.
- Song time is a smoothed estimate of DSP time minus the output latency.
- **Stalls:** if DSP time doesn't advance for `max(0.06, 4×buffer)` seconds, song time stops creeping ahead. The clock re-anchors after a jump larger than `max(0.05, 2.5×buffer)`. Per-frame creep is clamped to 0.1 s.
- **Pausing during the count-in** keeps the negative time (`_pausedRaw`); it used to jump to 0.
- **Schedules past the clip's end** run without audio.

`TapInput` uses input-event timestamps. Swipes are also checked at lift-off, so fast flicks count.

## Testing through the Unity MCP

Test in the editor through the Unity MCP tools, not by clicking the desktop.

**execute_code:**
- It runs on the CodeDom compiler (C# 6): no local functions, no tuples, and no new types.
- Use reflection for private fields: `cameraRig`, `clock`, `_layout`, `_tier`, and the `Chart` field (find it by `FieldType.Name == "Chart"`).

**Starting a song from code:**
```csharp
var gc = UnityEngine.Object.FindAnyObjectByType<DropBeat.GameController>();
int idx = gc.Library.songs.FindIndex(s => s.name == "Cosmic Trance");
gc.SelectSong(idx); gc.SelectDifficulty(DropBeat.Difficulty.Hard);
gc.StartSong(gc.Library.songs[idx], DropBeat.Difficulty.Hard, true); // true = autoplay
```

**Compiling:**
- Always stop play mode before scripts recompile. A recompile during play mode throws NullReferenceExceptions everywhere.
- New files need `refresh_unity` with scope `all`.
- To confirm a compile, wait until `Library/ScriptAssemblies/Assembly-CSharp.dll` is newer than the edited file. Use an until-loop; a long `sleep` is blocked. Then check `read_console` for errors.

**Editor settings:**
- Never force `QualitySettings.vSyncCount` in the editor. It stalls play mode when driven over MCP.

**Screenshots:**
- `manage_camera` screenshot with `include_image: true`, saved to `Assets/Screenshots`. That folder is not committed.

**Other checks:**
- **DropBeat > Validate Beat Analyzer** tests the beat analyzer on synthetic songs.
- `SongTools.MeasureSyncAverage` checks a song's sync.
- `TimingProbe` injects timed taps, duals and swipes.

**Charts:**
- After changing `ChartDesigner`, `MapDesigner` or `SongTwists`, re-check all 45 charts (15 songs × 3 difficulties):
  - The same map comes out on every play.
  - No notes are off the grid.
  - No duals or swipes inside Flip or Warp spans.
  - The pad launches on the beat.
  - No companions while the camera is in the tunnel.
  - Main-ball rings are at least 1.9 apart.

### Measuring what's on screen

Use this recipe for any camera change. In play mode, for times `t` stepped across a span:

1. Compute the ball and focus the way `GameController` does: `target2 = Lerp(ball, nextNote.position, 0.35)`, focus `(target2.x*0.35, target2.y+0.5, 0)`.
2. Call `rig.SetMode(mode, 0)`, set `rig.TwistRoll`, then call `rig.Snap(focus)`.
3. Project every note within 3.6 s ahead (the ring binding window) with `cam.WorldToViewportPoint`.
4. Take `max(|x-0.5|, |y-0.5|) * 2`; 1 means the screen edge.

Aim for 0.8 or less. Results for Cosmic Trance:

| | Worst value | Meaning |
|---|---|---|
| Before the warp fix | 1.52 | well off the edge |
| After the warp fix | 0.78 | comfortably on screen |

The game view's aspect ratio in the editor is about 0.46 (a portrait phone).

## Editing files from the shell

- **Line endings:** files use CRLF. Patch scripts must keep them.
- **Heredocs:** Bash heredocs that contain apostrophes break. Write a Python patch file with the Write tool instead, or use the Edit tool.

## Songs and tools

**Making songs:**
- `Tools/generate_songs.py` makes songs with ElevenLabs Music. Prompts are in `Tools/songs.json`. It reads `ELEVENLABS_API_KEY` from the environment only; never print or commit the key. A song of about 80 s costs about 1,090 credits on the Starter plan.
- `Tools/make_chiptune.py` synthesises 8-Bit Hero.

**Analysing songs:**
- After adding audio, run **DropBeat > Analyze All Songs**, then **DropBeat > Apply Song Themes**.
- Voltage Run needs a BPM override of 174; otherwise the analyzer picks 2/3 of the drum & bass tempo.

**Storage:** song audio is stored with Git LFS (about 38 MB).

## iPhone build (IPA) from Windows

Unity on Windows only exports the Xcode project. The `.ipa` is compiled by `.github/workflows/ios-ipa.yml` on a GitHub macOS runner.

1. In Unity, build iOS to `Builds/iOS`. `IosBuildPostprocess` enables 120 Hz.
2. Zip the folder's contents as `Builds/DropBeat-iOS-xcode.zip`, then upload it: `gh release upload ios-xcode Builds/DropBeat-iOS-xcode.zip --clobber`.
3. Push the commit to the `ios-build` branch, or run the workflow by hand.
   - The workflow runs `pod install` (the LevelPlay ads SDK), builds without code signing, and removes UnityRuntime's stale `_CodeSignature`. Without that step, iOS refuses the install with error 0xe8008001.
   - It attaches `DropBeat.ipa` to the release and to the run.
4. Install with Sideloadly. With a free Apple ID, re-install every 7 days.

**Testing on an iPhone with Unity Remote 5:**
- Input System 1.19 can't find `GenericRemote` in Unity 6000.5, so `Editor/UnityRemoteTouchFix.cs` hooks touch up.
- Set the remote device to iOS.Any, and plug the phone in after Unity starts.
